A counter that has to react before the clock does

A counter is a clocked circuit, but the specification asks reset and parallel load to take effect immediately. The design resolves that by splitting the 12-bit load into twelve one-bit asynchronous set/clear decisions, while normal counting stays on the clocked data path.

What the design does

  • Counts across the full 12-bit range, 0x000 to 0xFFF (0 to 4095).
  • Active-high asynchronous Reset forces Count to 0 immediately.
  • Active-high asynchronous Load forces Count to A[11:0] immediately.
  • Counts up or down on the rising clock edge when Enable is 1, and holds when Enable is 0.
  • Keeps the priority Reset over Load over count/hold.
  • Rolls over from 0xFFF to 0x000 and underflows from 0x000 to 0xFFF.

Operating modes

ResetLoadEnableUp_DownOperation
1XXXAsync Clear, Count = 0
01XXAsync Parallel load, Count = A
000XClocked Hold current Count
0011Clocked Count up by 1
0010Clocked Count down by 1

With modulo-4096 arithmetic, incrementing 0xFFF gives 0x000 and decrementing 0x000 gives 0xFFF.

Two layers: next-state logic and twelve bit-slices

A standard flip-flop has asynchronous set and clear pins, not a pin that loads an arbitrary bus. So for every bit, the load value A[i] is converted into its own set and clear signal. This maps cleanly onto standard-cell hardware.

Clocked path Asynchronous path

Per-bit control equations

// normal clocked operation
next_count = Enable ? (Up_Down ? Count + 1 : Count - 1) : Count

// asynchronous controls, bit i
clr[i] = Reset | (Load & ~A[i])
set[i] = (Load & A[i]) & ~clr[i]

Reset sits inside every clear signal, which guarantees it overrides an active Load.

Next-state layer

Computes next_count from the current Count, Enable and Up_Down. This is the only logic the clock edge touches.

Bit-slice layer

Twelve identical D flip-flops receive next_count[i] on D and set_i / clr_i on the asynchronous pins.

Normal operation

With Reset and Load low, all asynchronous inputs are inactive and the flip-flops update only on the rising edge of Clk.

From specification to layout in nine steps

The project follows the standard digital flow: define behavior, write RTL, prove it in simulation, map it to a cell library, then place and route.

XceliumRTL and gate-level simulation, SimVision waveforms
GenusRTL synthesis to standard cells
InnovusFloorplan, placement, clock tree, routing

  1. Specification analysis Spec

    Identify the data width, control inputs, priority order, count direction, hold operation and boundary behavior.

  2. Logic formulation Spec

    Write the next-state equation and derive the per-bit asynchronous set and clear equations for parallel loading.

  3. RTL coding Verilog

    Implement counter_12bit_updown and the reusable dff_async_set_clear submodule.

  4. Testbench development Verilog

    Generate a 10 ns clock and write directed tests for reset, load, up, down, hold, priority, rollover and underflow.

  5. Simulation Xcelium

    Compile design and testbench, run, add the important signals to the waveform viewer and check behavior against the spec.

  6. Debugging and refinement Xcelium

    Correct priority and testbench issues, and confirm that short asynchronous load pulses persist in the state.

  7. RTL synthesis Genus

    Synthesize with the selected standard-cell library and constraints, in both slow and fast process corners.

  8. Report analysis Genus

    Capture schematics plus timing, power and area reports, and compare them with the intended architecture.

  9. Physical implementation Innovus

    Import the netlist, then floorplan, place, build the clock tree, route and verify connectivity.

Reset and a narrow Load pulse

Reset clears Count at once, without a clock edge. A short Load pulse that rises and falls between clock edges still leaves 0xA55 in the counter, because the flip-flops are set and cleared asynchronously.

Up, down and hold

Count moves by one on each rising clock edge while Enable is high, in the direction set by Up_Down. With Enable low, Count holds, even while Up_Down toggles between edges.

Both ends of the range

Counting down from 0x000 wraps to 0xFFF, and counting up from 0xFFF wraps to 0x000. This confirms the modulo-4096 behavior.

Reset wins over Load

With both asserted, Count goes to 0x000. When Reset is released while Load is still high, Count takes the value on A (0xABC in the test).

What the mapping shows

The 12-bit parallel load maps onto the library's SDFFSRX1 flip-flop, which has the asynchronous set and clear pins the architecture needs. The counting logic and the per-bit set/clear decode sit around those twelve flip-flops.

Sign-off

DRC clean

The connectivity report shows no open or short nets. The first DRC run found 220 violations, caused by power stripes on the same metal layer. After the layer assignment was corrected, the check passed.

Discussion

The central obstacle was mapping a multi-bit parallel load onto a standard library. Splitting the input bus into independent set and clear signals for SDFFSRX1 flip-flops solved it, and Xcelium confirmed the result across all 19 directed tests, including the strict priority of Reset over Load and the modulo boundaries.

In synthesis, the slow corner gave a slightly larger area (229.482) at lower power (3935.009 nW). The fast corner shrank area to 227.430 but raised power to 6765.520 nW.

Conclusion

The project covers the full digital flow from behavioral RTL to physical layout. Mapping parallel load to per-bit set/clear pins delivered immediate state overrides while keeping counting synchronous. Genus and Innovus produced a DRC-clean layout with positive timing slack and a balanced power, performance and area result.
